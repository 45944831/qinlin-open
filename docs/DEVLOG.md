## 原始文档开头

手机本机直连亲邻云端网关的极简开门 App。

- **无 Web 服务层**：不需要服务器、域名、HTTPS 证书、Docker、公网暴露
- **无广告**：完全不启动官方 `com.qinlin.edoor`，广告 SDK 根本不运行
- **无第三方依赖**：纯 Android / JDK 标准库（HttpURLConnection + javax.crypto + org.json）
- **桌面小组件**：后续已加入 4 种版式（1×1 / 2×1 / 4×1 / 4×2），见文末「桌面小组件」章节
- 唯一的外部连接是亲邻官方 API —— 开门指令必须经其服务端实时校验，**不可能离线开门**

> 说明：本文按时间顺序追加排查与实测记录，早期章节描述的是当时的版本状态；
> 若与文末最新章节冲突，以文末为准。

## 功能

1. 输入手机号 → 发送短信验证码
2. 输入验证码 → 登录，`sessionId` 仅保存在本机 SharedPreferences
3. 刷新门列表 → 点选一扇门设为默认（保存 `communityId` / `doorControlId`）
4. 点「开门」→ 直接 POST `https://mobileapi3.qinlinkeji.com/api/open/doorcontrol/v2/open`
5. 凭证过期自动提示重新登录；可一键清除本机凭证

界面上明确提示：**成功响应只代表平台已接受指令，不等于物理门已打开**。

## 构建

离线构建，不需要 Gradle / AGP / Maven：

```bash
cd qinlin-app
python build-apk.py
```

产物：`qinlin-open.apk`（debug 签名，可直接 `adb install`）。

依赖：
- JDK 17（`E:\Java\jdk-17`）
- Android SDK `build-tools/29.0.3`（`C:\Program Files (x86)\Android\android-sdk`）
- `tools/android.jar`（API 33）

`build-apk.py` 顶部的 `SDK` / `JDK` / `ANDROID_JAR` 路径按本机实际修改即可。

**本仓库不含 Android SDK 文件与签名私钥**（体积大 / 不可外传），首次构建需自行准备：

```bash
mkdir -p tools && cd tools
curl -LO https://dl.google.com/android/repository/platform-33_r02.zip
python -c "import zipfile; z=zipfile.ZipFile('platform-33_r02.zip'); open('android.jar','wb').write(z.read('android-13/android.jar'))"
```

`build/debug.keystore` 由脚本用 `keytool` 自动生成，无需提交。注意 **新生成的密钥与旧 APK 签名不同**，
首次覆盖安装可能要先卸载旧包；真机登录凭证存在本机 SharedPreferences 中，卸载会丢失。

工具链：`aapt2` → `javac --release 8` → `d8` → 追加 `classes.dex` → `zipalign` → `apksigner`。

## 协议要点

协议事实参考 `burgesswu/ha-qinlin`（MIT）与公开资料，代码为独立编写：

- 网关 `https://mobileapi3.qinlinkeji.com`；短信 `gateway2.qinlinkeji.com/member/sms/sendSecurityCode`
- 登录 `/api/app/v1/login`；小区 `/api/app/user/v2/communityInfo`；
  门列表 `/api/app/user/v2/queryAllUserDoorByCache`；开门 `/api/open/doorcontrol/v2/open`
- `sign` = 按 key 字典序拼 `k=v&...` + 后缀，MD5 后转大写
- 手机号 AES-128-ECB / PKCS7，十六进制大写
- 请求头 `qvendor/openid/qversioncode/qversionname/qchannel/qplatform/user-agent`
  **必须小写发送**（网关对大小写敏感）
- `sessionId` 走 URL query；开门参数全部放 query，POST 无 body

## 重要风险与边界

- 这是**非官方客户端**，伪装 4.9.3 客户端并使用其协议常量。上游接口变更、加签名校验或风控都会导致失效。
- 上游项目 `CIoaRaShuYing/qinlinopen` **无 LICENSE**（默认保留所有权利），本项目未复制其源码。
- 项目作者的验证记录明确写着：**未验证真实短信登录、真实开门、HTTPS 部署**，
  连 Docker build 都未完成。因此本 APK 的开门能力**必须由你本人实测验收**。
- 首次测试务必**人在门内、带实体钥匙或门禁卡**，并保留官方 App 作为兜底。
- 仅用于本人账号、本人门禁；使用前请确认符合 App 用户协议与物业规定。
- `sessionId` 存本机明文 SharedPreferences（已设 `allowBackup=false`），
  不要在有 root / 已解锁的设备上长期存放；「清除本机凭证」可随时删除。

## 与「定向拦截广告域名」的关系

两条独立路线：
- 本 APK：彻底不用官方 App，去广告最彻底，但需自行承担非官方客户端的稳定性风险
- 定向域名拦截：继续用官方 App，低风险、可一键回滚，但广告位可能只是留白

建议先保留官方 App + 实体钥匙，把本 APK 作为实验性副方案验证通过后再考虑切换。

## 点击反馈 / 状态刷新修复（18:14）

用户反馈「点击按钮没反馈」「登录后状态未刷新」。复现与结论：

- logcat 证实点击事件被接收、Toast 也确实弹出，但**状态框一个字没变**。
- 根因：所有前置校验分支（验证码为空、手机号位数不对、未选默认门等）
  只调用 `toast(...)` 就 `return`，提示 2 秒即消失；而 `statusTv` 位于长页面底部，
  用户点完看到的仍是上一条旧状态，体感就是「没反应」。
- 修复：
  1. 新增 `notifyUser()`：校验提示同时写 Toast **和**状态框，反馈持久可见；
  2. `status()` 更新后自动 `smoothScrollTo` 到状态框（长响应时不会跑出可视区）；
  3. `async()` 每次操作额外弹即时 Toast，登录成功也弹「凭证已更新」；
  4. 状态框改为带蓝色描边/圆角/更大字号，初始提示不触发滚动，首屏仍从顶部开始；
  5. `renderDoors()` 结束后刷新「当前默认门」标签；
  6. `request()` 保存脱敏后的服务端原始响应到 `LAST_RAW`（抹掉 sessionId 与手机号），
     开门后直接显示在状态框，用于排查「平台说成功、物理门没开」。
- 门列表按钮附带服务端 `online` 字段；实测两扇门均返回 `online`，即设备在线。
- 协议对照：`burgesswu/ha-qinlin` 的 `open_door()` 也只用
  `appChannel/doorControlId/communityId` + query 中的 `sessionId/sign`，
  **没有额外的「每门 Token」参数**，本 APK 未漏字段。

## 新增常驻「开门区域」（18:47）

**可行性检查**：屏幕 1080×2400；原「开门」按钮在 `ScrollView` 内，门列表收起时

实现：

- 把「开门」操作从滚动区**提升到外层固定卡片**：`开门区域` 标题 + `切换门 ▸`
  + 当前默认门（含 communityId/doorId）+ 72dp 大红按钮 + 现场确认提示。

- 门列表按上游区域分组展示：`▸ 楼栋门 区域`、`▸ 小区门 区域`、`自定义门`、`其他门`；
  `QinlinApi.doors()` 的 kind 映射由「二选一」改为按 key 精确归类。
  `applyDoorSelection()` 跳过非 Button 子 View，分组标题不影响 ✓ 高亮。
- 新增 `switchDoor()`：在开门区里循环切换已加载的门，**只改默认门、不直接开门**
  （防止误触发物理开门）；未刷新过门列表时提示先点「刷新门列表」。
  门列表存于 `loadedDoors`，`renderDoors()` 时同步。
- `Door.label()` 把 `[在线:online]` 缩短为 `· 在线`，门按钮文字不再折行。
- 切换门用短 Toast「已切换开门区域」，长 Toast 只留给开门成功的「已开门」，
  避免提示气泡盖住下方日志区。

真机实测：防呆提示生效；刷新后出现两个区域分组且 ✓ 高亮跟随；

每扇门单独一个开门按钮（误触风险高，改用「切换默认门 + 一个开门按钮」）。

## 分类诊断日志（21:46）

### 为什么要做

原来的「日志」是 `statusTv.setText()` **单条覆盖**：刷新一次就丢、没有时间与分类、不落盘。
一旦遇到「覆盖安装后登录状态还在、但无法开门」，事后完全无法还原现场。
现在改为分类 + 分级 + 链路追踪 + 持久化 + 可导出。

### 日志模型

单行格式：`MM-dd HH:mm:ss.SSS  级别  分类  [traceId]  消息`

| 维度 | 取值 |
| --- | --- |
| 分类 | 系统 / 登录 / 门列表 / 开门 / 网络 / 界面 / 异常 |
| 级别 | `I` 信息、`W` 警告（含前置校验失败）、`E` 错误（含异常堆栈摘要）、`✓` 关键成功 |
| traceId | 每次后台操作生成 6 位 id 并绑定线程；点击开门 → 参数校验 → 组装请求 → HTTP 响应 → 业务码 → 结果全部同 id |
| 落盘 | `/data/data/com.wb.qinlin/files/logs/qinlin.log` 追加写，256KB 轮转为 `.1`；**覆盖安装 / 重启都不丢** |
| logcat | 同步输出，tag `QinlinLog`，可用 `adb logcat -s QinlinLog` 抓取 |
| 内存 | 最近 400 条，供界面实时显示 |

### 主界面日志区

状态框改为固定高度（210dp）的**彩色日志流**，内部可滚；E 红 / W 橙 / ✓ 绿 / I 深灰。
失败时自动把日志区滚到可见（顶部登录表单已移出 ScrollView，不会被推走）；平时日志刷新不滚页面。

- **筛选**：全部 → 开门 → 登录 → 门列表 → 网络 → 系统 → 错误（循环切换；「错误」只看 W/E）
- **复制日志**：诊断快照 + 最近 200 条，直接进剪贴板
- **导出日志**：系统文件选择器（SAF，无需权限）导出 txt = 快照 + 磁盘完整历史（含轮转文件）
- **诊断快照**：一键复制当前状态，适合直接发给开发者
- **清空日志**：清空内存与本机文件，不影响凭证与门设置

### 排障示例：覆盖安装后登录态还在但开不了门

1. 启动日志会明确标出 `检测到覆盖安装 / 版本变化：上次=… 当前=…`（对比 versionCode/lastUpdateTime 安装戳）。
2. 启动快照记录：版本 / 首装 / 更新时间、设备与 Android、`session` 指纹与**写入时间**、手机号脱敏、
   `openid` 指纹与**登录时 openid 指纹**、默认门 `cid/did/名称/区域/在线`、小区名。
3. 旧数据缺「登录时 openid」记录，或两者指纹不一致 → 启动与开门前各给一条 `W`，
   提示「服务端可能判定会话无效，建议重新登录」。
4. 点开门：`点击开门 | 参数快照 …` + 前置校验（session 为空 / 未选门）明确留痕。
5. 网络层：POST 路径（去掉含 sessionId 的 query）、body 长度、session/openid 指纹
   → HTTP 码 / 耗时 / 响应长度 / 脱敏摘要 → 业务 code、success、msg
   → `SESSION_EXPIRED` 或 `QINLIN_REJECTED` → 异常类型与前 4 帧堆栈。
6. 按同一个 traceId 把这些行串起来，或切「错误」筛选只看 W/E；点「导出日志」把 txt 发回即可定位。

## 启动与开门反应优化（2026-11-10 09:50）

针对「启动慢 / 点开门到反馈慢」做了一次全链路审查。瓶颈不在控件数量，而在三处：
日志同步落盘、每条日志全量重建界面、每次请求断开 TLS 连接。

### 发现的问题

| 环节 | 优化前 | 影响 |
| --- | --- | --- |
| 启动 | `AppLog.startup()` 在 onCreate 主线程做 2 次 PackageManager IPC、约 8 条日志，每条同步 `FileOutputStream` 开 / 写 / 关 + 3 次正则脱敏 | 首帧被日志 IO 推迟 |
| 启动 / 开门 | 每条日志都 `runOnUiThread(renderLog())`：复制 400 条内存日志、构造 60 个 Span、`setText` 重新测量、再 post 滚动 | 启动约 8 次、一次开门约 10 次主线程重建 |
| 开门 | `request()` 无论成败都 `conn.disconnect()`，底层连接池无法复用 | 每次开门都要 DNS + TCP + TLS 握手 |
| 正确性 | `LAST_RAW` 是全局 volatile，启动后台补小区名与开门并发时会串响应 | 开门日志里的服务端原文可能属于别的请求 |

### 已实施

- **日志 IO 全部异步**：`AppLog` 增加 daemon 单写线程 + `LinkedBlockingQueue`；
  `add()` 只在内存追加后立即返回，logcat / 落盘 / 轮转全在后台。`flush()`（2 秒上限、
  写线程自调用直接返回）在导出 / 清空 / 崩溃前保证落盘；`clear()` 也投递到同一写线程，
  杜绝主线程与后台抢同一文件。
- **日志流合并渲染**：60ms 内多条日志只 `renderLog()` 一次；
  `AppLog.recent(tag, errorsOnly, limit)` 改为倒序收集、命中即停，颜色常量提到循环外；
  `Entry` 时间戳只格式化一次。
- **连接复用**：响应流完整读完并关闭后不再 `disconnect()`，异常 / 流未读完才断开。
  启动时后台补小区名建立的连接可被后续开门复用，同域名请求省一次握手。
  **不缩短 readTimeout**：开门宁可多等，也不能因过早判失败让用户再点一次造成重复开门。
- **并发正确性**：`QinlinApi` 增加按线程隔离的 `RAW`，`openDoor()` 返回本次请求的响应原文，
  MainActivity 不再读全局 `LAST_RAW`。
- **零碎开销**：`newTrace()` 复用 `SecureRandom`；startup 只取一次 `PackageInfo`；
  `applyLoginState()` 在主线程直接执行、少一帧消息投递；
  开门按钮点击瞬间加 `performHapticFeedback`，不等网络就有按下反馈。
- **可观测**：新增「启动到首帧耗时 Xms」「开门端到端耗时 Xms」两条日志；
  网络层原有的「响应 ← HTTP 200 | 耗时 Xms」可看出连接复用效果。
- 附带：全局未捕获异常也写入 AppLog 并 flush，避免「闪退但日志为空」。

### 仍有的提升空间（本轮未做，需权衡）

- 门列表每次打开都重新联网读小区 + 门列表、无缓存；可加短 TTL 内存缓存 + 后台刷新，
  但门禁权限会变，过期策略要谨慎。
- `LAST_DIAG` 仍是全局 volatile，多链路并发时状态框摘要可能串线（只影响诊断文案）。
- 无网络预检：弱网要等 15s 读超时才提示；做预检需新增 `ACCESS_NETWORK_STATE` 权限。
- 界面全部用代码构建，无法享受 XML 布局的编译期优化；迁移成本高、收益有限。
- `communities()` 最坏串行 4 种请求格式，可缓存「上次成功姿势」跳过重试。
- 真机性能量化（Perfetto / Systrace）与正式签名密钥仍待发版处理。

`aapt2 compile/link` + `javac --release 8` 通过（59 个 class，仅 `PackageInfo.versionCode`
deprecation 警告）；反射单测 9/9 通过（flush 不阻塞、队列顺序、limit 过滤、时间戳格式、
脱敏未失效）。按默认规则**本轮未打包、未发布**，`qinlin-open.apk` 仍是 11-09 20:52 的旧包。

## 日志查看体验修复（2026-11-10）

真机反馈「日志不能滑动」。实测根因不是日志框不滚，而是三层问题叠加：

1. **手势被外层页面吃掉**：日志框在页面 ScrollView 内，手指位移一超过 touchSlop 就被外层拦截，
   TextView 自己的 `ScrollingMovementMethod` 收不到 MOVE，看起来完全不动。
   现在日志框在 `ACTION_DOWN` 就 `requestDisallowInterceptTouchEvent(true)` 接管手势，
   滑到日志顶/底再按方向余量交回外层，两层都能滚（`logMaxScroll()` 判断余量）。
2. **日志框永远露不全**：日志框固定 210dp（630px），而页面下半部只分到 385px 的滚动视口，
   滚到底也只能看到日志的一个角，手指一滑又是整页在动。现在高度按视口实测收敛
   （`fitLogHeight()`，96~210dp），并删掉与顶部账号卡片重复的「退出登录 / 清除本机凭证」，
   把高度让给日志框。
3. **自动跟底会打断翻看**：原来每次渲染都强制滚到最后一行，手动上滑立即被弹回。
   现在只在「用户仍在最新处」时跟底；离开底部后右下角出现「↓ 最新」，点一下回到最新并恢复跟随。

新增 `LogActivity` 全屏日志面板（工具条「⤢ 全屏日志」进入）：

- 独立 ScrollView + 惯性滑动；面板高度钉死（`setMinimumHeight`），避免筛选到「0 条日志」时
  Dialog 窗口跟着内容塌成一小块（真机已复现并修复）。
- 只认「✕ 关闭」和返回键退出（`windowCloseOnTouchOutside=false`）：日志是排障现场，
  误触外部就消失会丢掉上下文。
- 支持筛选 / 复制 / 自动跟随 / 「↓ 回到最新」。

顺带修掉一个更隐蔽的 bug：`AppLog.setListener` 是单例，全屏日志界面销毁时会把主界面的订阅
一起清空，回到主界面后日志不再刷新（真机复现：点开门没有新日志）。改为
`addListener / removeListener` 多订阅（`CopyOnWriteArrayList`）。

真机验证（测试机B / Android 13 / 1080×2400）：主界面日志框完整可见、框内上下滑动生效、
「↓ 最新」出现/消失正确；全屏面板 77 条日志可滑、可回到底部、关闭正常；主界面日志实时刷新。

## 桌面小部件「快捷开门」（2026-11-10）

目标：不用先打开 App，在桌面上点一下就开门。

**结构**

| 文件 | 作用 |
| --- | --- |
| `src/com/wb/qinlin/OpenWidget.java` | `AppWidgetProvider`：负责卡片状态、点开后的开门执行、结果回写 |
| `src/com/wb/qinlin/WidgetOpenReceiver.java` | 开门点击的落点，`exported="false"`，只能被本应用的 PendingIntent 触发 |
| `res/layout/widget_open.xml` | 4×2 卡片：门名行 / 红色开门按钮 / 状态行 |
| `res/xml/widget_open_info.xml` | 250×110dp、可横向纵向缩放、`updatePeriodMillis=0`（不轮询） |
| `res/drawable/widget_bg.xml`、`widget_btn_red/busy/blue.xml` | 卡片底与三种按钮底色 |

**交互**

- 点红色「开门」→ 直接下发指令，不打开 App；按钮立刻变「开门中…」，结果写回同一张卡片的状态行。
- 点门名行 / 状态行 → 打开 App 看详情（避免想开设置时误开门）。
- 未登录 / 未选门 → 按钮变蓝「打开应用」，状态行提示「登录并选门后，这里直接开门」。
- 结果行：`上次：3分钟前 · 已开门`（绿）/ `上次：昨天 09:51 · 失败 SESSION`（红）/ `无网络`。
- 防连点：请求在途时忽略重复点击（`inFlight` 25s 兜底）；请求未结束时按钮不再指向开门。
- 状态刷新时机：开门完成、App 回到前台、登录/退出、换门。没有定时唤醒，不额外耗电。

**为什么不用 Service**

targetSdk 33 下从后台起前台服务要处理通知权限与前台服务类型，为几秒请求引入一整套前台服务不值；
这里用广播接收器的 `goAsync()` 把生命周期延长到请求结束，是官方支持的最小做法。

**安全**

- `OpenWidget`（provider）必须 `exported="true"`，否则桌面收不到 `APPWIDGET_UPDATE`。
- 真正开门的 `WidgetOpenReceiver` **不导出**：第三方应用发同名广播会被系统丢弃（实测 `am broadcast` 后进程都未被拉起），
  桌面点击走 PendingIntent，发送时以本应用身份执行，因此不导出也送得到。

**真机验证（测试机B / Android 13）**

| 项目 | 结果 |
| --- | --- |
| 系统注册 | `dumpsys appwidget` 可见 `com.wb.qinlin/.OpenWidget`，250×110dp、resizeMode=3、updatePeriodMillis=0 |
| 版式 | 用真实 `RemoteViews.apply()` 渲染六种状态（可开门 / 开门中 / 上次失败 / 4×3 放大 / 未登录 / 已登录未选门），无裁切、无换行错乱（`widget-render-1.png`、`widget-render-2.png`） |
| 开门链路 | 以本应用身份发出与桌面点击相同的广播 → 真实打到 `/api/open/doorcontrol/v2/open` → 服务端 401 → 按设计清凭证并把卡片切成「未登录」 |
| 日志 | `开门 [trace] 桌面小部件触发开门 | ... | 入口=桌面小部件（未打开界面）` 与 `小部件开门：凭证已失效 → 已清除本机凭证` |
| 越权 | `adb shell am broadcast -n com.wb.qinlin/.WidgetOpenReceiver` 进程未被拉起，外部无法触发开门 |
| 崩溃 | FATAL EXCEPTION = 0 |

**注意：小部件只能加到桌面，加不到负一屏。**
OPPO 负一屏（「我的服务」那一屏）用的是 ColorOS 自有卡片引擎，只接受系统/合作方卡片，不托管第三方 AppWidget。

## 修复：桌面小组件开门不进 App 记录（2026-11-11）

用户反馈：**「桌面小组件开门记录，不会显示在 app 里面呢？」**

### 根因

两处，都和「小组件在后台被点、不打开界面」有关：

1. **主因 —— 记录写漏**：`OpenWidget.openNow()` 只写诊断日志（`AppLog`）和桌面卡片状态
   （`Prefs.setWidgetLast`），**从不调用 `OpenRecord.add()`**；而主界面的
   「最近开门记录 / 今日开门 / 上次开门 / 上次响应」全部读 `OpenRecord`。
   只有 `MainActivity.doOpen()` 的 `finally` 里写了记录，于是小组件开门在 App 里查无此事。
   源码注释声称「与 App 内共用同一份日志、不做第二套实现」，实际这一环漏了。
2. **附带 —— 日志页读不到后台进程的历史**：`LogActivity` 用 `AppLog.recent()` 只读
   **进程内存 `MEM`**；小组件由广播拉起进程写日志并落盘后，进程可能被回收，
   用户再打开 App 是全新进程、`MEM` 为空，那次开门日志只在「导出 / 复制全部」里存在。

### 修复

- `OpenRecord`：记录新增 `from` 字段（`widget` / `app`），JSONL 向后兼容
  （旧行无字段 → `optString("from","")` → 不显示标签）；新增 `sourceLabel()`。
- `OpenWidget.noteResult()` 升级为**唯一写记录点**：一次同时写本机开门记录 + 桌面卡片状态，
  成功 / 失败（含未登录 / 未选门 / 无网络 / 凭证失效 / 网络异常）都记。
- `MainActivity` 去掉自己那份 `OpenRecord.add()`，改走 `noteResult(..., FROM_APP)`，
  消除「两套实现」并避免重复记；写入在 `refreshStats()` 投递之前，保证界面读到的是新记录。
  `onResume()` 原本就会 `refreshStats()`，所以回到 App 即可看到，无需改刷新时机。
- 主界面记录行追加来源标签，例如「已开门 · 示例楼栋门 · 小组件」。
- `AppLog` 冷启动在日志写线程 `hydrate()`：解析磁盘尾部最多 400 行回填 `MEM`
  （`Entry.parse()` 与 `line()` 格式严格对应），先补历史再写本次启动行，保证时间顺序；
  每进程只回填一次，不重复写盘。诊断日志页因此也能看到后台小组件那次开门。

### 验证

- `python build-apk.py` 全链路通过，`qinlin-open.apk` 87880 bytes，v2 / v3 签名 true；
  签名证书 SHA-256 `47d376a0…681`（仍是同一个本地 debug keystore，**可覆盖安装、不丢凭证**）。
- dex 中 `sourceLabel / hydrate / readLines / recordDoor / noteResult` 均存在；
  日志行解析正则用真实样例（`✓` 级别、中文分类、JSON 原文、异常堆栈）5/5 匹配，
  非法行正确跳过。
- **真机当前不在线，未做现场验证**。待覆盖安装后实测：点桌面小组件开门 → 回 App，
  「最近开门记录」应出现带「小组件」标记的新行，且「今日开门 / 上次开门」同步；
  再在日志页确认小组件那次开门的诊断日志可见。

## 登录态保活与「自动被登出」修复（22:3x）

### 现象

用户反馈：本 APK 的登录状态不能持续在线，过一阵会被自动登出；官方 App 没有这个情况。

### 根因

- 网关 401 原文是「您还没有登录，或者**登录已超时**，请重新登录！」——
  **服务端会话本身有超时**，不是本机凭证被系统清掉。
- 旧实现 4 个入口（主界面开门 / 启动补小区名 / 门列表 / 小部件）一遇 401 立即
  `Prefs.clearSession()` 并切回登录表单，把「票据超时」变成不可恢复的「本机被登出」；
  网关偶发误判、网络抖动也会造成同样后果，只能重新收短信。
- 旧实现零后台活动：4 份小部件声明都是 `updatePeriodMillis=0`，Manifest 无 Service / Alarm，
  App 只在用户主动操作时发一次请求，会话长期空闲必然超时。
- 官方 APK（v5.3.2）静态提取到 `app/v1/checkLogin`、`_updateCacheSessionId`、`getSessionId`、
  `CheckLoginRedirectMixin`、`oneClick/appLogin`；官方有登录态检查、票据更新、静默登录
  与后台活动，因此用户感知不到过期。完整证据与未验证假设见 `docs/API-CONTRACT.md` 第 10 节。

### 改动

- 新增 `SessionGuard.java`：30 分钟节流探活、401 二次确认、手动重试，统一维护
  `session_expired` 标志；`checkLogin` 被业务拒绝时自动回退到已验收的 `communityInfo` 续期。
- `QinlinApi` 新增 `checkLogin()`（`/api/app/v1/checkLogin`，无凭证探测确认 ALIVE）
  与 `loginDetailed()`（留存完整登录响应，日志只记字段名）；业务响应顶层若出现
  `sessionId` 先留痕、不自动替换（对应官方 `_updateCacheSessionId` 线索）。
- `Prefs` 新增 `loggedIn / sessionExpired / lastKeepAlive / loginData`；

更可能是同期官方 App 重新登录 / 后台静默重登造成的互踢。

「绝对 TTL vs 滑动续期」仍无定论，但**无论哪种，30 分钟探活都挡不住互踢**。

**结论 3（原始问题的真正根因）**：官方 App 拥有微信 / 一键登录(SY) / 华为 / 荣耀 /
Apple 等多种登录渠道（静态提取：`interfaceWxLogin`、`goWxLogin`、
`interfaceAppLoginBySyToken`、`goSyOneLogin`、`interfaceHwLogin`、`appleLogin`、
`LoginChannelProxy`、`appWxOpenId`、`unionId`、`getAuthCode`），
配合 `checkLoginAndRedirect` / `pushLogin` 在会话失效时**静默重登**，用户无感；
自制 APK 只有短信验证码登录，一旦被踢只能人工收短信。旧代码再把 401 直接

**O1 门列表漏解析 `commonlyUsedDoor`**
`parseDoors` 原来只按 `optJSONArray` 取分组，而该键在上游是**单个对象**，整键被跳过。
改为「数组优先，取不到再按单对象解析」，并对单对象打印字段名。
真机实测 `data` 字段：`["authorizeExpired","buildingDoorList","commonlyUsedDoor","customDoorList",
"gateDoorList","hasFouce","isForceSubscribeWechat","userDoorDTOS"]`，`commonlyUsedDoor` 字段含

**O2 `code 121` 单独映射**
`121` = 签名或签名头不被接受（缺头 / 时间戳越界 / 签名不匹配）。以前归入 `QINLIN_REJECTED`，
与「门离线 / 无权限」提示相同；现抛 `SIGN_REJECTED` 并给出「协议版本头可能过期」的指引。
