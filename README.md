# qinlin · 无广告 APK

![平台](https://img.shields.io/badge/platform-Android-green)
![构建](https://img.shields.io/badge/build-aapt2%20%7C%20javac%20%7C%20d8-blue)

手机本机直连 qinlin 云端网关的极简开门 App：不启动官方 `com.qinlin.edoor`，广告 SDK 不运行，
不需要服务器 / 域名 / HTTPS 证书 / Docker，也没有第三方库。

> **解决什么**：官方 App 广告多，且登录一次就会把别处的自制客户端踢下线。本项目把开门能力收敛成
> 「登录一次 → 凭证加密存本机 → 按需探活 → 直连开门」：不做后台保活、不偷偷轮询，被踢后只提示重登。

## 核心特性

**构建与隐私**
- 纯 Android / JDK 标准库，离线构建（`aapt2` → `javac` → `d8` → `zipalign` → `apksigner`）
- 短信登录一次，`sessionId` / 手机号 / 登录响应经 **AndroidKeyStore AES-GCM 加密**后存本机
  （`allowBackup=false`，历史明文启动时自动迁移）
- 不做后台保活：只在启动 / 回前台 / 开门前按需检查会话；服务端判失效只标记、不删凭证，可点「重试连接」恢复

**开门与状态**
- 主界面一键开门；门列表放在二级页面，主界面只显示当前选中的门
- 主界面显示会话剩余有效期（服务端下发的滑动过期窗口），临近到期才转为提醒
- 开门成功弹「已开门」横幅，状态框保留脱敏后的服务端原文；**失败不进开门历史**（只更新小组件状态与诊断日志）
- 应用内 / 桌面小组件开门都计入同一份本机记录（标注来源），今日次数与最近记录同步
- 门列表状态区会提示上游的**门禁授权到期标记**（`authorizeExpired`），便于提前去官方 App 续期

**桌面小组件**
- 4 种尺寸（1×1 / 2×1 / 4×1 / 4×2），**每个小组件可独立设置名称、主题色并绑定不同的门**
- 主界面「组件设置」浮层：顶部横排标签列出所有已放置组件（名称 + 尺寸），逐个改名（限 5 个字）、
  换主题色（6 套，按钮与卡片底色一起变）、指定控制的门；改完立即刷新桌面外观
- 多个组件互相独立：点其中任何一个开门，**只有被点的那个**显示「开门中」，其它组件外观不变

> 开门指令必须经 qinlin 服务端实时校验，**不可能离线开门**。
> 平台返回成功 ≠ 物理门已打开，请现场确认并保留钥匙兜底。

## 构建

```bash
python build-apk.py              # 产物 qinlin-open.apk（debug 签名）
adb install -r qinlin-open.apk

python run-tests.py              # core 纯逻辑自检（33 条用例，不需要 Android 设备）
```

依赖 JDK 17、Android SDK `build-tools`、`tools/android.jar`（API 33）。
**换机器不用改代码**，按下面任一方式指定路径即可：

| 变量 | 作用 | 默认 |
|---|---|---|
| `JAVA_HOME` | JDK 根目录 | 找 PATH 里的 `javac`，再退回历史路径 |
| `ANDROID_SDK_ROOT` / `ANDROID_HOME` | Android SDK 根目录 | `C:\Program Files (x86)\Android\android-sdk` |
| `ANDROID_BUILD_TOOLS` | 指定 build-tools 目录 | `build-tools/29.0.3`，不存在则取最新 |
| `QINLIN_VERSION_CODE` / `QINLIN_VERSION_NAME` | 覆盖版本号 | 提交数 / `1.1-<短 commit>` |
| `QINLIN_KEYSTORE` | 指定签名密钥库 | `build/debug.keystore`（首次自动生成） |

**仓库不含 SDK 文件与签名私钥**，首次构建需准备 `android.jar`：

```bash
mkdir -p tools && cd tools
curl -LO https://dl.google.com/android/repository/platform-33_r02.zip
python -c "import zipfile; z=zipfile.ZipFile('platform-33_r02.zip'); open('android.jar','wb').write(z.read('android-13/android.jar'))"
```

> ⚠️ **签名密钥要备份**：`build/debug.keystore` 丢失后就再也无法覆盖升级，
> 只能卸载重装（本机登录凭证会一起丢）。换正式分发时用 `QINLIN_KEYSTORE` 指向自己的 keystore 并离线保存。
> 另外 `versionCode` 默认取 git 提交数，没有 `.git` 的源码压缩包会退回 Manifest 里的 `2 / 1.1`。

## 使用

1. 输入手机号 → 获取验证码 → 登录
2. 点门卡上的「切换门 ▸」进入二级列表，点选设为默认门（保存 `communityId` / `doorControlId`）
3. 回主界面点「开门」；若服务端判登录失效，先点「重试连接」，仍不行再重新短信登录
   （原因与处理见下节「登录为什么会失效」）
4. 登录后账号行会显示「凭证 N 天」——这是服务端下发的会话剩余有效期，正常开门/探活会自动续期，
   不需要手动干预；只有剩余不足 30 天才转为「凭证仅剩 N 天」提醒
5. 可选：桌面添加小组件，直接点小组件开门
6. **小组件设置**：主界面门卡底部点「组件设置 ▸」，或直接点桌面卡片上的组件名，进入设置浮层。
   顶部横排标签列出已放置的每一个组件（显示名称 + 尺寸），点标签切换；可为它改显示名
   （**最多 5 个字**，汉字/字母/emoji 都按 1 个字算）、选主题色（红/蓝/绿/紫/橙/青，
   按钮与卡片底色一起变）、指定控制的门。**1×1 按钮会显示组件名，并按字数自动缩小字号
   （5 个汉字约 8sp，正好占满格子）**；未设名字时仍显示「开门」，开门中显示「开门中」。
   名称与颜色存在本机，改完立刻生效，**不触发任何网络请求**；
   桌面上没有组件时会给出添加指引。多个组件时每个都可独立配置

## 登录为什么会失效（真机实测结论）

**结论：绝大多数「自动被登出」不是凭证到期，也不是本 APK 没做后台保活，
而是服务端按「账号维度单会话」互斥——任何一次新登录都会作废旧 `sessionId`。**

2026-11-12 真机互踢实验：`checkLogin` 对同一枚凭证返回 `code:0`；随后在官方 App
里用微信重新登录一次，约 1 分钟后同一枚凭证立刻变成 `code:401`
「您还没有登录，或者登录已超时」。对照日志还显示：空闲 13 小时 36 分仍能开门，
而短空闲后反而失效 —— **与空闲时长无关**，早期「48 小时绝对 TTL」的猜测已被推翻。

官方 App 之所以看起来「一直在线」，是靠一键登录 / 微信 OAuth / 厂商账号等多套
静默重登渠道自动换新票；本 APK 不复制该机制，也不做后台轮询
（轮询挡不住互踢，只会耗电）。官方 App 改用短信验证码登录也走同一个
`/api/app/v1/login`，不会拿到长效凭证，同样会触发互踢。

| 会让本 APK 失效 | 不会让本 APK 失效 |
| --- | --- |
| 在官方 App 重新登录（微信 / 一键 / 短信均可），**最主要原因** | 覆盖安装、重启手机、长时间不使用（实测 13h36m 空闲仍有效） |
| 官方 App 重装 / 换设备登录 / 服务端风控强制重登 | 只用 App 开门而不用小组件（小部件只是第一个发现 401，不是原因） |
| 上游协议变更 / 风控拦截（表现类似，但 `code` 不同，看日志区分） | 网关偶发误判的 401：本 APK 会二次确认，确认误判就自动恢复 |
| 服务端确实回收会话（较少见，日志表现为 `checkLogin` 也返回 401） | 除主动「退出登录」外的任何本地操作（凭证一直保留） |

**失效后的表现与处理**

1. 界面显示「本机凭证仍在，但上次被服务端判为失效（常见原因：官方 App 重新登录踢掉本会话）」；
   **只标记过期，不删除 `sessionId`**，只有主动「退出登录」才真清凭证。
2. 先点「凭证已失效？点此重试连接」：用 `checkLogin` 二次确认，
   网关误判 / 网络恢复时原地回到登录态，不必重新收短信。
3. 确认仍返回 401（确属被踢），才重新收一次短信登录。
4. 想少被踢：日常固定只用本 APK；一旦在官方 App 里登录过，就预期本 APK 需要重登，
   不要让两个 App 长期同时保持登录态。

> **关于「续期」的更正（2026-11-16）**：早期版本这里写的是「没有长效票据、无法续期」，
> 真机抓包后需要分开讲——
> - **会话本身是滑动过期的**：每次带 `sessionId` 的有效请求都会刷新窗口，
>   `checkLogin` 返回的 `data` 就是这个剩余窗口（实测 `7776000`，即 **90 天**）。
>   所以日常开门这个动作本身就是续期，**不需要定时任务**。
> - **真正无解的是被互踢**：官方 App 重新登录会作废整枚 `sessionId`，
>   滑动过期再长也救不回来。这也是本 APK 不做后台轮询的原因——轮询挡不住互踢，只耗电。
> - 登录响应里确实**没有 refresh token**，所以被踢后只能重新短信登录，无法静默换票。

## 凭证有效期与门禁授权到期

两个不同的「到期」概念，界面与日志里分开呈现：

| 概念 | 来源 | 表现 |
| --- | --- | --- |
| **会话有效期** | `checkLogin` 返回的 `data`（秒） | 账号行显示「凭证 N 天」；< 30 天转「凭证仅剩 N 天」并记告警。正常使用即自动续期 |
| **门禁授权到期** | 门列表 `data.authorizeExpired` | 门列表状态区提示「上游标记有到期限制」。**只提示、不判定失效** |

`authorizeExpired` 的官方语义尚未公开，实测本账号该值为 `1` 而开门完全正常，
因此实现上只做信息展示。若哪天开门提示无权限，请先去官方 App 确认门禁授权是否需要续期
（官方 FAQ 说明：业主到期自动续期，租客需手动申请，到期前 30 天官方 App 会在首页提醒）。

## 协议要点

协议事实参考 MIT 项目 `burgesswu/ha-qinlin` 与公开资料，代码为独立编写。

- 网关 `https://mobileapi3.qinlinkeji.com`；短信走 `gateway2.qinlinkeji.com`
- 登录 `/api/app/v1/login` → 按需会话检查 `/api/app/v1/checkLogin`（返回剩余有效期秒数）→
  小区 `/api/app/user/v2/communityInfo` →
  门列表 `/api/app/user/v2/queryAllUserDoorByCache` →
  开门 `/api/open/doorcontrol/v2/open`
- 门列表备用接口 `/api/app/user/v2/queryUserDoorByCacheNew`：主接口失败或返回空时才调用，不抢先
- `sign` = 参数按 key 排序拼 `k=v&...` 加后缀，MD5 转大写；手机号 AES-128-ECB / PKCS7
- 设备请求头必须**小写**；`sessionId` 走 URL query
- 请求头按 `qversioncode: 3146` / `qversionname: 5.2.6` / `User-Agent: Dart/3.8` 伪装，
  签名体里的 `version` 与 `qversionname` 保持一致

**门列表返回结构**（真机实测 `data` 字段）
`["authorizeExpired","buildingDoorList","commonlyUsedDoor","customDoorList","gateDoorList","hasFouce","isForceSubscribeWechat","userDoorDTOS"]`
其中 `commonlyUsedDoor`（服务端指定的常用门）是**单个对象**而非数组，其余分组为数组。
解析时「数组优先，取不到再按单对象」，避免只出现在该键的门被整扇漏掉。

**错误码语义**（用于区分「凭证失效」「协议过期」「门不可用」）

| 表现 | 含义 | 本 APK 的处理 |
| --- | --- | --- |
| `code:401` / HTTP 401 / 登录失效文案 | 凭证被作废 | 抛 `SESSION_EXPIRED`，二次确认后才提示重登 |
| `code:121` | 签名或签名头不被接受（缺头 / 时间戳越界 / 签名不匹配） | 抛 `SIGN_REJECTED`，提示协议版本头可能过期 |
| HTTP 5xx | 上游异常 | 除 `message` 外还读 `exception` / `error` 字段（`message` 常是 `No message available`） |
| 其它 `code != 0` | 门离线 / 无权限 / 业务拒绝 | 抛 `QINLIN_REJECTED`，附带脱敏后的服务端原文 |

**弱网策略**：小区列表接口有 4 种请求姿势的兼容尝试，但只在「响应格式不符」时才换下一种；
遇到网络层失败（超时 / 断网 / TLS）直接放弃，不再串行试 4 次，避免弱网下等满 4×20 秒；
上游返回 5xx 时同样立即停手（属服务端故障，换 body 格式不会恢复）。

## 风险与边界

- **非官方客户端**，伪装官方 `5.2.6`（`qversioncode 3146`）并使用其协议常量；上游变更 / 风控会使其失效。
- 参考项目 `CIoaRaShuYing/qinlinopen` 无 LICENSE，本项目未复制其源码。
- 仅供本人账号、本人门禁使用，请确认符合 App 用户协议与物业规定。
- `sessionId` 已用 AndroidKeyStore（AES-GCM 256，别名 `qinlin_creds_v1`）加密后存储，
  不再有明文凭证落盘；但密钥与密文同在设备内，已 root / 已解锁设备仍建议避免长期存放。
  Keystore 不可用时降级为明文并记日志，不会因为加密失败而丢登录态。
- 开门已真机验收通过；仍建议保留实体钥匙与官方 App 兜底（上游变更、凭证过期、设备异常时）。
- **服务端按账号单会话**：在官方 App 里重新登录（含微信 / 一键登录）会立刻作废本 APK 的凭证。
  避免两个 App 同时保持登录态；被踢后先点「重试连接」确认，必要时重新短信登录。
  官方 App 靠多套静默重登渠道维持「一直在线」，本 APK 不复制该机制，也不做后台轮询耗电。
  完整触发场景、真机互踢证据与恢复步骤见上文「登录为什么会失效（真机实测结论）」。
- `QinlinApi.java` 内的 APPID / APP_SECRET / AES 密钥是**上游公开协议常量**（非个人凭证），
  代码运行必需，故保留明文。
- **不要把协议常量当成安全边界**：APK 可被反编译，任何写在客户端里的 `APP_SECRET` / 盐值都能被提取；
  手机号 AES-ECB 与 MD5 签名只保证「请求格式对得上」，**不是机密性保护**。真正的安全边界是服务端
  对 `sessionId` 的校验，以及本机 Keystore 对凭证的加密。
- **本机日志的隐私边界**：日志已抹掉 sessionId / token / openid / 验证码 / 手机号明文（只留指纹与掩码），
  但含机型、系统版本、小区名与门名。`复制最近` 在 Android 9 及以下会先提示一次
  （那代系统的剪贴板对所有前台应用可见）；分享日志前请自行确认。
- **门列表缓存属于账号**：退出登录 / 换账号会清空；弱网下某个小区读取失败时，会沿用上次缓存里的门
  而不是把它们从列表里删掉，状态区会写明「沿用上次缓存」。

## 常见问题

**Q：为什么会自动登出？是不是 App 没做后台保活？**
A：绝大多数不是凭证到期，而是服务端按**账号维度单会话**互斥——在官方 App 里重新登录
（微信 / 一键 / 短信均可）会立刻作废本 APK 的 `sessionId`。后台轮询挡不住互踢，只会耗电，
所以本项目只做按需探活 + 401 二次确认。详见上文「登录为什么会失效」。

**Q：能让它和官方 App 同时在线而不互踢吗？**
A：不能。单会话是服务端按账号生效的硬约束，与客户端形态无关——原生 App、快捷指令、网关都一样。
唯一「不互踢」的前提是**这个账号只被本 APK 一端使用**，别再去官方 App 登录。

**Q：iOS / 快捷指令能用吗？**
A：本项目是纯 Android Java 项目，产出 APK，iOS 装不了也没有对外接口。iOS 上大致三条路：
① 用官方 iOS App（有广告、同样受互踢影响）；② 部署一个网关服务（如 `Lee65535/Qinlin-Gate-Worker`），
用网页 / Telegram 开门，但网关登录会踢掉本 APK，二者只能二选一；③ 照 `docs/API-CONTRACT.md`
用 Swift / Scriptable 另写一个客户端（工作量最大）。iOS 快捷指令的「运行 JavaScript」是受限环境，
无法引入 AES 库，纯快捷指令连登录请求都构造不出来。

**Q：为什么不把编译好的 APK 传上来？**
A：仓库只提供源码供参考，包体不入库（`.gitignore` 已排除所有 `.apk`）。按上文「构建」离线打包即可；
首次构建生成的新 keystore 与旧包签名不同，覆盖安装前可能需先卸载（会丢本机登录凭证）。

**Q：官方 App 已经 5.3.3 了，为什么不追新版本头？**
A：签名公式里的 `version` 必须是 `5.2.6`（有公式实证），开源客户端也明示兼容 `5.2.6 / 3146`。
官方更新日志只有「性能优化 / 修复 Bug」，没有协议或签名变更；盲目追版本号反而可能触发校验失败。

**Q：这些协议常量和密钥安全吗？算破解吗？**
A：APPID / APP_SECRET / AES 密钥是上游公开协议常量（非个人凭证），代码运行必需，故保留明文；
个人凭证（手机号 / `sessionId` / 登录响应）则经 AndroidKeyStore 加密后存本机。本项目是非官方客户端，
仅供本人账号与本人门禁使用，请自行确认符合用户协议与物业规定，并保留实体钥匙兜底。

| 路径 | 内容 |
| --- | --- |
| `src/com/wb/qinlin/` | 全部 Java 源码（界面、协议、缓存、日志、小组件） |

| `src/com/wb/qinlin/SecureStore.java` | 本机凭证加密层（AndroidKeyStore AES-GCM + 字段名 AAD，含明文/v1 自动迁移） |
| `src/com/wb/qinlin/Errors.java` | 统一错误文案（网络异常 / 业务码 → 人话），两个界面共用 |
| `tests/CoreSelfTest.java` | core 包自检（38 条用例），`python run-tests.py` 直接跑 |
| `src/com/wb/qinlin/Ui.java` | 设计基元：dp、字号/圆角阶梯、带涟漪的圆角背景、Toast 与应用内提示条 |
| `res/values/colors.xml` | 全局语义色板（浅色）；四个界面与小部件共用，`values-night/` 为深色版本 |
| `res/drawable-xxhdpi/` | 小组件选择器预览图（`previewImage`，@3x），由脚本生成，改布局后重跑即可 |
| `res/` | XML 布局 / drawable / 小组件配置 |
| `tools/make-widget-previews.py` | 用系统 Edge 无头模式把复刻布局截图成透明 PNG（本机无 PIL，纯离线） |
| `build-apk.py` | 离线构建脚本（SDK/JDK 走环境变量，版本号由 git 注入） |
| `run-tests.py` | 零依赖测试入口（只需 JDK，不需要 Android SDK） |
| `docs/DEVLOG.md` | 完整排查与真机实测记录（按时间追加，已脱敏） |
| `docs/API-CONTRACT.md` | 真实接口契约、官方 APK 路径清单、备用路径与防失效规则 |
| `docs/api-baseline.json` | 无凭证探测基线（15 条） |
| `api-probe.py` | 接口探测脚本：`python api-probe.py`，无凭证、只读、不触发开门 |
